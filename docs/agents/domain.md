# 领域文档

本仓采用单上下文：根 `CONTEXT.md` 是术语唯一来源，决策共用根 `docs/adr/`。`app/` 与 `tools/` 是目录职责，不是不同领域上下文。

## 探索之前

1. 按根 `AGENTS.md` 了解项目形态与硬性纪律；应用行为查 `app/说明书.md`。
2. 读取即将改动区域相关的根 ADR（`docs/adr/`）。

这些必读文件缺失时报告具体缺口并停止依赖该依据的改动，不能把缺失当作默认授权。

## 技能路径适配

工程技能模板中的 `GLOSSARY.md` 在本仓对应 `CONTEXT.md`。消费或更新术语时直接使用现有文件，不另建同义术语表；也不创建 `GLOSSARY-MAP.md`、`CONTEXT-MAP.md` 或目录级 ADR 副本。

需要记录新术语或决策时，依 `domain-modeling` 规则更新根 `CONTEXT.md` 或在根 `docs/adr/` 新增 ADR。

## 术语与决策冲突

issue 标题、提案、假设与测试名使用 `CONTEXT.md` 定义的术语，避开其中列出的混淆同义词。尚未定义的概念先核实是否存在真实缺口，再交由领域建模处理。

当前入口与任务状态以根 `AGENTS.md` 与已生效 ADR 为准。旧 SHA、旧工单、旧路径与历史文档一律不可引用（ADR 0001：查证历史去备份盘），不回写成现行流程。

若拟议改动与现行 ADR 冲突，指出具体 ADR、冲突行为和理由，交用户裁定后再实施；不能用模板示例或历史计划静默覆盖现行决策。
