# 派生启动缓存与已验证写回

为缩短完整界面的可见等待，同时不降低写回正确性，决定采用“并行完整扫描＋只读缓存界面＋后台实际 SHA-256 核验”。无缓存或缓存不可用时，按既定顺序枚举，在原有预算内有上限地并行读取、解码并计算全部文件哈希，重建内存态后再开放写回。有干净缓存时，可先恢复完整、可浏览但只读的界面；后台仍执行同一条完整扫描，不得减少文件范围或以缓存哈希代替磁盘实际哈希。

缓存是由快照派生的可再生成副本，不是数据真源、作品身份清单或备份来源。设置与机密不从缓存恢复，回收站、服务锁和缓存目录自身也不进入缓存；缓存内容不进入快照、AI 上下文或备份导出。缓存按数据根和版本隔离，原子落盘；损坏、截断、超大、跨根、版本或元数据不符均回退完整扫描，读写或落盘失败不影响正文真源、服务启动和退出。

## Considered Options

- 只做并行完整扫描：保留最简单的信任模型，但无法缩短已有缓存时完整界面的感知等待。
- 用路径、大小和 mtime 命中后直接开放写回：拒绝。元数据相同不能证明内容相同，同大小同 mtime 的外部修改会漏过这种检查。
- 并行完整扫描加只读缓存界面（采纳）：以额外的派生存储和后台核验换取更快可浏览，同时保持写回只信当次磁盘结果。

## Consequences

- “缓存界面可见”与“已验证就绪”是两个不同阶段；首帧、缓存命中或 `ST.ready` 单独变化都不能证明已经可写。
- 缓存读取前须校验封装、路径、条目、缓存内文本哈希和当次元数据；这些检查只足以决定是否展示只读副本，不能免除后台全量复核。
- 后台扫描发现的磁盘差异须在开放写回前替换缓存投影和文件账本，并保留用户核验期间改变的视图。只有当次已验证账本可作为后续 CAS 的 `baseHash`。
- 扫描以每文件实际读取及紧随其后的元数据复查认领内容；普通元数据变化只触发一次有界重扫。复查无法辨识的同大小、同 mtime 改写及复查后的外部写入由后续写回 CAS 拦截；不以全量双扫宣称消除这些并发窗口。
- 后台核验失败时保持只读并报告错误；任何情况下都不得把缓存内存投影写回磁盘。
