# 空段落非规范数据与段间距纯显示层

正文存储沿用「contenteditable HTML 原样进出」的数据契约，段间「空行」在存储里表现为空段落块；各章空行数量不一源于手工空行与富文本粘贴，属历史脏数据。决定：空段落一律视为非规范数据，由「一键排版」删除全部空段落并清理段首空格，存储规范定为「每段独占一块、无空段落」；唯一例外是全空小节保留既有空正文壳 `<p><br></p>`，这是编辑器空正文契约，不用于表达段距。段落间距属视觉偏好，做成外观体系的显示层设置（数值、全局一份），仅作用于编辑区正文段落的显示，绝不写进正文存储；导出与 AI 上下文维持既有压平口径，不承诺任何段距。段间距出厂默认目前为 0.2em，待试用后定稿；当前八套出厂方案暂共用该默认。

## Considered Options

- 沿用空段落表达段距（现状）：间距混入内容导致各章不一致，视觉偏好无法与正文分离、不可迁移；拒绝。
- 只做显示层设置、不清理存量：含空段落的章无法给出一致段距视觉，设置形同虚设；拒绝。
- 删空段落＋段间距入显示层（采纳）：存储只保留结构语义（正文段/引用/小标题/折叠块/插图），间距归显示层，与 ADR 0004「消费侧压平」的既有事实一致。全空小节的空正文壳不在此列。

## Consequences

- 一键排版会改变存储形态（删空段落），必须走编辑器撤销栈、按小节回退（有改动的景各压一条快照）。
- 全空小节保留单个 `<p><br></p>` 壳，不算违反「无空段落」规范，也不表示段距。
- 「统一为每段独占一块」指存储规范形态；视觉段距由外观设置决定。日后若要求导出文本带可调段距，属导出层新决策，不回写本口径。
- 段间距默认值尚未经用户试用定稿，程序与文档均按临时默认披露，不得写成已确认默认。
- ADR 0004 的场景纯文本块级换行是消费侧口径，不受本决策影响。
