# 场景纯文本口径统一与守卫式哈希迁移

`scenePlainText` 从 `textContent` 改为块级换行口径后，持久化章交接记忆的 `sourceTextHash`（`sha256:` / `fnv1a64:` 两种算法前缀）将与存量不符。决定守卫式迁移：按存档哈希前缀选算法、用旧口径重算比对，仅当与存档一致且章序/章名仍有效（seqAt/titleAt 口径）时，才改写为新口径哈希（沿用存档前缀同算法）；验证不过（无前缀、不匹配、章序章名失效）一律不迁移——已过期的保持过期、缺基线的仍需重新生成，绝不无条件重算（会把陈旧记忆复活成新鲜基线）。仅驻内存的整理/修订候选基线无存量，不在迁移范围。

## Considered Options

- 接受一次性过期、逐章手动重生成：否——重生成＝逐章一次模型调用（付费），且无廉价「重冻」入口。
- 守卫式迁移（采纳）：见正文。
- 不动 `scenePlainText`、各 AI 出口单独换行：否——双口径分裂，S13 之外的链路继续丢段落边界。

## Consequences

- 迁移后回滚程序版本：新口径哈希会全部判「过期」——安全失败（停注），不产生错误注入；迁移幂等，可重跑。
- 实施时重写原「禁动 scenePlainText」注释（S13 注释）并引用本 ADR，同步更新说明书。
